# macOS 27 Apple API and platform claim register — 2026-10-22

This register separates documented platform behavior from RustUI design concepts. Apple Developer documentation and WWDC sources were checked on 2026-10-22. Claims marked unverified must not be used as platform requirements or runtime promises. The prior environment inspection recorded Xcode 26.1.1 / macOS SDK 26.1; that SDK cannot validate macOS 27 declarations locally.

| Claim or API | Status | Evidence and design consequence |
|---|---|---|
| `NSRefreshController` adds pull-to-refresh support for `NSScrollView` in macOS 27.0. | Confirmed in macOS 27 release notes. | Native AppKit capability. A RustUI `ScrollView` or theme token does not provide this behavior by itself. [macOS 27 release notes](https://developer.apple.com/documentation/macos-release-notes/macos-27-release-notes), [NSRefreshController](https://developer.apple.com/documentation/appkit/nsrefreshcontroller). |
| `NSToolbarItemGroup` adds a semantic `role`; `NSSegmentedControl` has roles including `tabs`. | Confirmed in macOS 27 release notes. | Keep toolbar groups, segmented selection, and tab navigation semantically distinct. Native VoiceOver and appearance behavior belongs to AppKit; a RustUI style record alone cannot supply it. [macOS 27 release notes](https://developer.apple.com/documentation/macos-release-notes/macos-27-release-notes), [NSToolbarItemGroup](https://developer.apple.com/documentation/appkit/nstoolbaritemgroup). |
| macOS 27 refines toolbar scroll-edge effects and adds the interactive Liquid Glass effect and view corner-concentricity API. | Confirmed in WWDC26 AppKit session. | Prefer platform APIs for native toolbar material and view-corner behavior. A RustUI radius/opacity token is not a substitute for `NSScrollEdgeEffectStyle`, `NSViewCornerConfiguration`, or native glass interaction. [Modernize your AppKit app, WWDC26](https://developer.apple.com/videos/play/wwdc2026/289/). |
| macOS 27 introduces a toolbar-minimization API or new toolbar-minimization behavior. | Unverified in the official sources retrieved for this register. | The retrieved WWDC26 session supports scroll-edge effects, toolbar material refinements, and concentricity; it does not substantiate a new toolbar-minimization claim. Keep the claim out of the design contract until an exact Apple source/API is identified. [Modernize your AppKit app, WWDC26](https://developer.apple.com/videos/play/wwdc2026/289/). |
| macOS menu item image visibility changes and `preferredImageVisibility` can control it. | Confirmed, with SDK/linkage-dependent behavior. | Release notes describe symbol-image hiding by default and a `preferredImageVisibility` override. Preserve the exact native default/compatibility conditions; do not infer a universal menu-image rule from a mockup. [macOS 27 release notes](https://developer.apple.com/documentation/macos-release-notes/macos-27-release-notes). |
| `NSControl.Events` provides semantic and tracking events. | API existence and semantics confirmed; macOS 27 introduction/availability not established by the retrieved page. | Treat event delivery as an AppKit interaction contract. Do not label it “new in macOS 27” without an availability source. [NSControl.Events](https://developer.apple.com/documentation/appkit/nscontrol/events). |
| `ControlWidget` is a SwiftUI protocol for a control displayed in system spaces; Mac controls can appear in Control Center or as menu bar items. | API concept and Mac placement confirmed; macOS 27 introduction not established here. | P40 is a design preview, not an in-app RustUI control. Real controls use WidgetKit, SwiftUI templates, and App Intents and have extension/system ownership. [ControlWidget](https://developer.apple.com/documentation/swiftui/controlwidget), [WidgetKit Controls](https://developer.apple.com/documentation/widgetkit/controls-collection). |
| “ViewAnnotations” is a macOS visual annotation API. | Partly corrected; exact API symbol and SDK availability unresolved. | The singular testing type `ViewAnnotation` belongs to App Intents Testing and is not itself a general SwiftUI annotation API. Separately, Apple's [WWDC26 macOS guide](https://developer.apple.com/wwdc26/guides/macos/) describes a View Annotations capability for mapping views to entities. Confirm the exact public declaration before naming an API. Neither establishes a RustUI design/runtime API. |
| Liquid Glass appearance can be adjusted from “ultra clear” to “fully tinted.” | Confirmed in Apple's WWDC26 Platforms State of the Union. | Keep the user-adjustable appearance axis and accessibility adaptations in the platform/environment model. A specific default midpoint or a “no ultra-clear” restriction is not supported by this source. [Platforms State of the Union, WWDC26](https://developer.apple.com/videos/play/wwdc2026/102/). |
| macOS 27 supports the “Show Borders” environment value. | Confirmed in Apple's WWDC26 Platforms State of the Union. | Model as an accessibility/environment input with a control fallback; do not encode it as a static color alone. [Platforms State of the Union, WWDC26](https://developer.apple.com/videos/play/wwdc2026/102/). |
| A specific Launchpad replacement is a macOS 27 platform feature. | Unverified in the official Apple sources retrieved for this register. | Do not name a replacement, claim a migration, or model it as a RustUI component without an authoritative source. Treat Launchpad and its alternatives as OS-owned surfaces. |

- The release-notes page is living and can contain beta/RC material. The cited macOS 27 page is the source for release-specific claims; API reference pages establish API purpose, not by themselves the first supported OS version.
- The documentation confirms native platform capabilities, not RustUI support. The local theme candidate and its screenshots remain design evidence only.
