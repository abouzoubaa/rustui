# PX-4 latency references (local diagnostics only)

These files are not Cargo workspace targets and are not shipped. Build explicitly with `./scripts/build_latency_refs.sh`, which uses the pinned release dependencies and produces binaries in ignored `target/headstart/px4/`.

- `latency-appkit 60`: native AppKit `NSTextView`, 1200 × 800 content points, ordinary keyDown handling, alternating x/backspace at 10 Hz after two seconds warmup. Each input also changes a marker layer's contents. The measurement ends at the first CADisplayLink callback after NSTextView has drawn that version. This is a **refresh-opportunity proxy**, not an observed Metal presentation or proof of scanout; it cannot establish the exact AppKit key-to-screen floor. The raw callback timestamp and targetTimestamp are retained for analysis. Never compare its proxy to Metal presentedTime as if their endpoints were identical.
- `latency-gpui 60`: a minimal focused ASCII text input using GPUI Fast's div/key handler only; no RustUI runtime or GPUI Kit. It supports x/backspace for this controlled reference, not a full editor/IME. The binary links the same pinned Fast libraries as the Lab release. Run with `RUSTUI_DAMAGE=0 RUSTUI_FRAME_LOG=buffered RUSTUI_FRAME_PROFILE=1 RUSTUI_G0_LATENCY=1 RUSTUI_LATENCY_BREAKDOWN=1` to use exactly the Lab's raw mach-clock stages and actual Metal drawable presentedTime endpoint.

The AppKit proxy and bare Fast reference have intentionally different capabilities from the 10,000-line RustUI typing scene. They isolate framework scheduling from editor work; they are not replacements for matched scene measurements.

## G5 controls (opt-in, local only)

`./scripts/build_g5_refs.sh` builds `target/headstart/g5-1/latency-gpui`, `latency-metal`, and `latency-appkit-display` with the pinned release dependencies. The build also makes a byte-identical `G5 Bare.app` wrapper for native inspection and paired runs. These are separate local references; the PX-4 proxy remains available for historical reproduction.

- `latency-gpui 60`: bare input with version-per-edit and final-text validation. Set `RUSTUI_G5_INPUT_HZ=10` or `30`, `RUSTUI_G5_REFRESH=1`, damage off and the buffered/PX-4 diagnostics. `GPUI_FAST_IMMEDIATE_PRESENT=1` enables the candidate; `GPUI_FAST_IMMEDIATE_TRANSACTION=1` additionally tests transaction presentation. Both behavior switches default off. `RUSTUI_G5_FULLSCREEN=1 MTL_HUD_ENABLED=1` selects the native fullscreen control; fullscreen alone is **not** proof of Direct mode. Observe the HUD's Direct indicator separately.
- `RUSTUI_G5_REFERENCE=1 latency-metal 60`: standalone immediate Metal control, VSync on. Uses actual drawable presentedTime and GPU end time, with an acquisition-duration record for every nextDrawable call. The same input-rate and transaction switches are supported. Completed/presented callbacks retry dirty state; the pool remains bounded.
- `RUSTUI_G5_REFERENCE=1 latency-appkit-display 60`: actual NSTextView edits and a black/white version barcode published after text drawing. ScreenCaptureKit decodes the pixels and records the frame's WindowServer displayTime. Six warmup edits prime capture before the two-second measurement boundary. Screen recording access is required. This measures compositor display time for captured versions, not a callback opportunity or physical photon scanout; capture coverage must remain explicit.

`refresh.m` passively records CADisplayLink timestamps for the bare example without rendering or requesting a preferred refresh rate. Callback delivery cadence is reported independently from the display's advertised maximum. `scripts/g5_latency.py` leaves missed-refresh counts unavailable until supplied a measured control floor; it never treats a missing floor as zero misses.

The G5-1 continuation uses `GPUI_FAST_IMMEDIATE_HOLD_MS=250` while the master immediate switch is on; zero isolates the prior no-hold path. Scheduled demand during the burst uses the GPUI immediate queue, and live resize cancels the hold. Diagnostics record input-time attachment/queue state and actual display-link stop/recreate events. `g5_latency.py --slow-output <path>` writes each input above its capture median plus one observed refresh, with the frame path and lifecycle timeline.

`pixel_capture.swift` is compiled into both the native AppKit control and a local dynamic library for the bare GPUI reference. `RUSTUI_G5_PIXEL_CAPTURE=1` paints a version barcode into GPUI's scene and captures it using the same filter, configuration, decoder and WindowServer displayTime as AppKit. GPUI also retains its Metal presentedTime measurement. The library and references are local test tools, outside workspace releases.

Run sets separately with `RUSTUI_G5_REFERENCE=1 RUSTUI_G5_SET=hold|screen|transaction ./scripts/run_g5_bench.sh <output>` (choose one value). `all` runs those three sets in order; `immediate` separately compares the master switch. Each set uses five alternating matched pairs per input rate. Screen pairs compare GPUI (arm 0) with AppKit (arm 1), and are latency controls rather than a P-rule CPU feature verdict. Build first and keep all local compilation/profiling stopped while recording.
