# G5-2 — frame-source candidates

These are experimental candidate paths. All new switches default to off. Damage stays off, and the owner decides adoption from the measurements. The candidate is a hashed, reversible patch in `patches/candidate-fast-latency/`; owned GPUI sources are regenerated by script.

## Owner decision — NSView not adopted

NSView stays behind `GPUI_FAST_VIEW_DISPLAY_LINK=1`, off and unused. The owner classified hover latency as **NEUTRAL**: median **29.60 → 29.81 ms**, p95 **38.23 → 38.14 ms**. Process CPU is **REGRESSION** (>3% in all five pairs); distinct versions shown fell below 110/s in **3/5** captures. No further NSView captures or optimization are planned.

The completed drag comparison had median **30.47 → 29.94 ms**, p95 **35.88 → 38.32 ms**, CPU **INCONCLUSIVE** (paired changes −10.28%, +0.60%, +8.37%, +1.15%, −11.71%), and below 110 distinct versions/s in **3/5** NSView captures. Both arms had zero observed out-of-order presentations. These are five matched 60-second pairs, measured on a loaded machine; latency entries are medians of capture quantiles, not pooled quantiles. No overall NSView win is adopted.

## Safety patch on G5-1

`gpui-fast-present-order-safety-v1-fast` is a separate hashed, reversible candidate immediately after G5-1. It contains the per-surface submitted-version/source-cohort guard, capacity checks for ordinary legacy callbacks, and pending dirty retry. Its new logic is in `fast/present_order.rs` in core, Apple and macOS. The existing G5-1 switch enables these safety fixes. The NSView experiment follows as a separate candidate, remains off and is not used by the G5-1 path. The Ahead switch remains retired.

Forced Legacy is checked for correctness only: typing 30/s and hover, with no latency or CPU verdict. It uses existing CVDisplayLink plus G5-1 immediate presentation and safety, without experimental frame-ahead pacing.

## Runtime selection and supported systems

RustUI's packaged minimum is **macOS 13.0**, declared by `LSMinimumSystemVersion` in [the Playground bundle](../../apps/rustui-playground/macos/Info.plist). No macOS 13 VM was found in the installed VM tools and local VM inventory, so real macOS 13 functional execution is not verified. VM results would not establish latency.

Selection uses the running OS version and selector/class availability, with no compile-time OS-version choice:

| Runtime | Selected source |
| --- | --- |
| `GPUI_FAST_FORCE_LEGACY_LINK=1` | Existing shared CVDisplayLink registry |
| macOS below 14 | Existing CVDisplayLink; G5-1 immediate admission remains available |
| macOS 14+, `GPUI_FAST_VIEW_DISPLAY_LINK=1`, factory available | NSView display link on the main run loop |
| macOS 14+, otherwise | CAMetalDisplayLink when available; CVDisplayLink otherwise |

The exact selector tests include macOS 12, 13, 14 and 27, unavailable factories, and the force-legacy override. The NSView factory and its macOS 14 availability are checked against the pinned binding and AppKit SDK header. Objective-C runtime messages use the same three-float `CAFrameRateRange` layout/encoding as the existing latency observer. Approved Cargo manifests and verification scripts remain unchanged.

## Scheduling

The Ahead arm is retired. Mixing scheduled-future CAMetalDisplayLink drawables with immediate drawables can reverse presentation order. Its completed bare-hover comparison increased median input-to-presentedTime latency from 30.28 to 45.72 ms (median of capture medians); it is not part of the remaining matrix. `GPUI_FAST_FRAME_AHEAD` no longer enables that arm.

All remaining opt-in arms, including the G5-1 baseline, use independent order guards for the base, overlay and each extra composition surface. Each renderer has its own identity, in-flight count, last submitted version and source cohort. A source switch waits only for that surface's acquired drawables to be presented. A busy base never defers an available overlay. Frame callbacks and immediate admission proceed when any surface can draw; submission flags reset per frame, and each layer's availability wakes the window. The base's display-link restoration checks only the base cohort.

Submission rejects versions older than that surface's last submission, with equal versions allowed. Production uses the painted-scene generation; diagnostics use the painted input version. Tests cover base typing with independent popover/extra-surface progress, overlay dragging while the base pool is full, and the unguarded 8 → 6 → 7 inversion followed by guarded drain/order recovery independently on all three surfaces. Display-order analysis keys observations by window and surface, so legitimate cross-layer presentation interleaving is not counted as an inversion.

The NSView and forced-legacy candidates retain a per-renderer generation gate for command buffers awaiting scheduling; this does not replace the drawable-lifetime order guard. A stale completion cannot release a successor. Active input requests 80/120/120 pacing on the NSView source and resets it when quiet. Actual cadence remains measured independently.

`GPUI_FAST_VIEW_DISPLAY_LINK=1` selects the NSView source when supported and enables the frame-ahead guard. Continuous frames and immediate input frames acquire with `nextDrawable` only below the same tracked pool capacity. This source stays attached, uses no CAMetalDisplayLink attach/detach and arms no G5-1 hold timer. Its main-run-loop tick samples activity, requests 80/120/120 while active, and resets/pauses when quiet. Window teardown invalidates it.

Every explicit acquisition under the G5-1 master switch uses the capacity guard, including ordinary legacy callbacks with neither an immediate-input scope nor an experimental pacing flag. The force-legacy arm uses the existing CVDisplayLink registry, with G5-1 immediate presentation and the same capacity/handoff checks. A deferred, coalesced waker restores a stopped legacy subscription for asynchronous invalidation. The native callback timestamp is captured on the CV thread and consumed on the main queue, so callback-to-draw includes that queue delay. The NSView and Metal timestamps are captured at their callback entries.

## Measurement protocol

Build once with the pinned release toolchain and finish local verification before recording. No compiling, profiling or other heavy local work overlaps timing. All arms use damage off, buffered frame logging and identical diagnostic flags. Every capture takes getrusage snapshots after warmup and reports process user+system CPU per attempted present. CPU verdicts follow [the P rule](MEASUREMENT_RULES.md), with five adjacent matched off/on pairs, alternating off→on and on→off. Each measured window is 60 seconds.

`scripts/run_g5_frame_sources.py` compares:

| Comparison | Off | On | Workloads |
| --- | --- | --- | --- |
| View | G5-1 baseline, with order safety | NSView source | Bare hover, drag, typing 30/s, then typing 10/s |
| Legacy | G5-1 baseline, with order safety | Forced CVDisplayLink | Bare hover, then typing 30/s |

The driver follows that priority order, preserving five adjacent matched pairs per comparison. The reduced matrix has 60 measured one-minute windows plus normal warmup and load checks. It reserves time to push/report and never shortens a measured window to fill the timebox. After an implementation fix, previous paired verdicts are discarded and the priority matrix restarts on the new frozen build. An unfinished comparison receives no P verdict. Short functional controls are not acceptance measurements.

Each capture preserves the top-five process snapshot, corrected background load, actual source selection, all acquisitions over 1 ms and their path/in-flight/detach details. The owner-authorized CPU-gate bypass remains labeled **measured on a loaded machine**. The acquisition gate is no call over 2 ms inside measured windows; warmup outliers remain listed separately. A source-selection assertion prevents a fallback path from silently passing another source's test.

Reports include input→presentedTime median/p95/max, GPU-complete→presented median, missed refreshes against the disclosed control floor, observed refresh cadence, distinct versions shown/s, presentation gaps, rendered-never-shown frames, callback→draw delay, acquisition counts, process CPU paired changes/verdict and frames over 8.3 ms. Missing measurements remain unmeasured. Final text/version and monotonicity checks apply to every valid capture. The bare controls include changed hover highlights and a moving card, not just dispatched events.

The passive refresh observer does not request a rate or present frames. It is linked into the bare reference and injected only into the opt-in lab captures. It buffers timestamps and writes after timing. Results and any adoption decision belong in the ticket PR and batch report; raw capture logs stay uncommitted.
