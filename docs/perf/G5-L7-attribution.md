# G5-L7 native-input attribution

## Content-matched comparisons

Each comparison used five matched pairs, alternating order. Each capture
ran for 60 seconds after warmup at 10 posted X/Backspace keys per second,
delivered through Cocoa. The apps launched directly. GPUI used display
sync off, passive display link off, damage off, buffered logging and
prepaint reuse on. The L2 sync-off and L4 timing probes were applied to
the release measurement build. AppKit used its normal compositor.

Both single-line arms started empty. The same source generated by Lab
was loaded into the AppKit reference. Both large-document arms inserted
and removed one character near the start of the first line. AppKit used
Menlo Regular at 13 pt and matched the editor’s 19.5 pt line height.
Lab retained its syntax colors, gutter and fold markers. Every content
window measured 1,200 × 800 pt at 2× backing scale. The source
editor viewport was about 1,136 × 700 pt in both apps.

Latency values are pooled keystroke medians and p95s. The common clock
is ScreenCaptureKit `displayTime` of the first decoded version marker.
P ends at Metal `GPUEndTime`. The miss rate uses the L4 proxy
`SCK − GPU end ≥ 8.333 ms`, with a denominator of matched, non-negative
margins. AppKit has no exposed Metal completion timestamp for its
text frame, so P and that miss rate are unavailable. Process CPU is
the median across captures of user-plus-system CPU seconds per wall
second from `getrusage`. This denominator works across both app
implementations. CPU per attempt is also shown for GPUI.

median ScreenCaptureKit endpoint and 0.870 ms slower at p95 than bare

1.93× the process CPU per second. The measurements describe these apps
under the observed load and their respective compositor paths.

were not measured. The miss-rate column uses the nominal L4 threshold.

## Handler and prepaint attribution

`xctrace` produced no samples. Time Profiler failed its launch probe
with a DTServiceHub connection error, and its high-frequency attach
attempt did not find the running Lab process. The fallback was a
60-second main-thread Samply capture at 2,000 Hz, with symbolized
release stacks. These results are Samply estimates.

Samples had to fall within the native handler entry-to-exit or prepaint
window. CPU weights were prorated by the interval overlap. Nested
layout intervals were removed from prepaint. The timestamp offset
came from the capture's mach clock and epoch start marker. Inclusive
time counts a symbol once per sampled stack and overlaps up the call
tree. Self time belongs to the sampled leaf. System functions are
listed by library when source lines are unavailable. macOS system
addresses were symbolized with the host's dyld shared cache where possible.
Inclusive lists start at `native_send_event` or `Window::draw_roots`
and omit app startup and run-loop ancestors.

The unmarked handler samples include AppKit focus lookup through
`SLPSGetKeyFocusProcess` (0.015 ms/key in the Mach message leaf), ObjC
message dispatch, GPUI application effects, and some editor work outside
the named L6 subspans. The handler as a whole also sampled 0.136 ms/key
inclusive in `TextWrapper::update_wrapped`. At least 0.027 ms/key of the
handler's memory-copy leaf appeared under the RustUI CodeEditor change
subscription and `App::flush_effects`. Those parent and child times
share samples.

Inside prepaint, `TextElement::prepaint` accounts for 0.072 sampled
inclusive ms/key. Visible highlight lookup and the reuse checks both
appear below it. The stacks rank observed CPU, and their sampled weights
cover only part of the sub-millisecond windows. The remainder of the
1.162 ms unmarked handler span and 0.448 ms prepaint span cannot be
assigned to individual functions with this capture.

## Overdraw on one editor keystroke

This is the scene for native edit version 4 from a separate diagnostic
capture. Bounds are clipped to the drawable and draw content mask.
The occlusion check used actual draw order and required a later
solid, opaque quad to contain the whole rectangle. Rounded clipping
and transparent borders cannot certify whole-rectangle coverage.

| ---: | --- | --- | ---: | --- |
| 1 | GPUI Kit root window background, `WindowState::style` → `Style::paint` | (0, 0)–(2400, 1600) | 3,840,000 | No |
| 2 | CodeEditor input background, `Input::render` → `Style::paint` | (64, 64)–(2336, 1464) | 3,180,800 | No |
| 3 | Editor line-number gutter, `TextElement::paint` | (66, 66)–(204, 1462) | 192,648 | No |
| 4 | Editor active-line fill, `TextElement::paint` | (78, 82)–(2314, 122) | 89,440 | No |
| 5 | CodeEditor input left border strip, identified by bounds and radius in `Style::paint` / `Window::paint_quad` | (64, 67)–(77, 1461) | 18,122 | No |

The first two quads contribute 7,020,800 clipped pixels when overlap
is counted. The editor background overlaps most of the root window
fill, while the padding and rounded corners leave some of the root
visible. Whole-quad elimination alone cannot remove that overlap.

## Benchmark controls

For the Lab single-line arm, set `RUSTUI_G5_L7_SINGLE_LINE=1`. For
the matched editor arm, set `RUSTUI_G5_L7_MATCH_EDITOR=1`. An untimed
Lab typing run can export its canonical source via
`RUSTUI_G5_L7_EXPORT_DOCUMENT=/path/to/source.rs`. Pass the exported file
to the AppKit reference as `RUSTUI_G5_L7_DOCUMENT=/path/to/source.rs`,
with `RUSTUI_G5_L7_FONT=Menlo` and `RUSTUI_G5_L7_FONT_SIZE=13`. Run all
arms with the native `scripts/run_g5_budget.py` runner, external observer,
direct launch, `--hz 10 --seconds 60 --passive 0 --pixels 1`, and the L6
scheduler and sync-off settings.
